## Лабораторная работа №1

**Базовая формулировка:**
Реализовать межпроцессное взаимодействие через файл дескриптор (лучше через tcp сокет).
Нужно сделать 2 приложения (C/C++), одно с ролью клиента, второе с ролью сервера. Они должны обмениваться сообщениями ping (клиент), pong (ответ от сервера). Для безопасного взаимодействия, алгоритмика должна соответствовать диаграмме состояний (на примере файла, см. рисунок).

Для максимального балла только C/C++, только std и уделить внимание обработке ошибочных ситуаций.

---

Выше будет оцениваться, если будет написан простенький чат с возможностью получения истории переписки, где файловый дескриптор можно использовать как транспортную шину (в случае использования файла).

Ещё выше, если приложения будут собраны любой системой сборки (к примеру cmake или meson).

## Лабораторная работа №2

Имплементировать алгоритм параллельных вычислений, варианты предметных областей:
1) Параллельная обработка графических данных (инверсия цветов, либо размытие, либо иной алгоритм обработки графических данных)
2) Параллельная обработка набора текстовых данных (см картинку 2 во вложении)
3) Иной параллелизуемый алгоритм
 
---

Дополнительные условия:

На >=8 баллов:
Для тех кто хочет максимальный балл, требуется реализация не через создание потоков (механизм fork для параллелизации) или использование thread pool, а с помощью реализации шаблона Producer->Consumer
Особым шиком будет использование блокирующей очереди (не обязательно переизобретать велосипед), из которой потребители сами забирают объекты для обработки.

---

Механизм ожидания завершения обработки одного цикла параллелизации в этом случае может быть различным, но интереснее всего будет увидеть такую реализацию, которая решает задачу потоковой обработки большого набора данных с помощью распараллеливания вычислений. Например использовать ещё одну очередь, куда будут складываться результаты. правда тут уже будет нужна аккуратная синхронизации, просто блокирующая не подойдет.
